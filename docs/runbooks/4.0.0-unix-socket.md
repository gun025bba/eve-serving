# Runbook: gateway 4.0.0, trusted unix socket + dedicated `_evegw` user

Status: **not executed**. 건영 runs the `sudo` steps himself. The agent can run only steps marked *(no sudo)*.
Why: before 4.0.0, `127.0.0.1:8000` trusted `Tailscale-User-Login` from any local process (security review: HIGH).
4.0.0 trusts identity headers only on a unix socket that only `tailscale serve` (root network extension) and the
gateway user can reach. Any process can still connect to TCP, but there it gets API-key auth only.

Placeholders: `<TS_HOST>` = the Mac's ts.net name, `<ME>` = 건영's macOS login. Never paste secrets into a shell
history line. Use an editor on the 0600 files instead.

## 0. Decisions

| Item | Decision |
|---|---|
| Service user | `_evegw` (hidden, no login shell, own group `_evegw`) |
| Layout | `/opt/eve-gw/{bin,etc,web,run,log}` owned by `_evegw`. `etc` and `run` are 0700. `run/gw.sock` is 0660 |
| Launch | `/Library/LaunchDaemons/com.llmserving.gateway.plist` with `UserName=_evegw`. The old LaunchAgent is removed |
| Secrets | DB URL and API key go in `/opt/eve-gw/etc/` (0600 `_evegw`), **not** in the plist |
| `tailscale serve` | `https:443 / -> unix:/opt/eve-gw/run/gw.sock`. Funnel stays off |
| TCP `:8000` | **Keep it on 127.0.0.1, API key only** for phase 1. Identity headers are stripped there, which closes the HIGH. Local scripts, health checks and rollback keep working. Log audit (3.0.0 to 3.1.0): there was no API-key traffic on :8000. Phase 2, after 7 days with no `auth_provider=api-key` requests in the log: set `GW_TCP_DISABLED=true` (see §6) |
| pf | Optional. See §5 |

## 1. Pre-checks *(no sudo)*
```sh
export PATH=/opt/homebrew/bin:$PATH
cd ~/llm-serving && git fetch --tags && git checkout v4.0.0 && make build BIN=bin/gateway-4.0.0
./bin/gateway-4.0.0 -version                          # 4.0.0
dscl . -read /Users/_evegw 2>&1 | head -1             # expect eDSRecordNotFound
dscl . -list /Users UniqueID | awk '$2==451'          # expect empty, else pick another free id < 500
dscl . -list /Groups PrimaryGroupID | awk '$2==451'   # expect empty
ps -axo user,comm | grep -i 'tailscale.*network-extension'   # must run as root (standalone/macsys Tailscale)
tailscale serve --help | grep -q 'unix:' && echo serve-unix-ok
tailscale serve status; tailscale funnel status       # note current state, for rollback
```
Back up:
```sh
cp -p bin/gateway bin/gateway.v3.1.0.bak
cp -p ~/Library/LaunchAgents/com.llmserving.gateway.plist ~/Library/LaunchAgents/com.llmserving.gateway.plist.pre-4.0.0
tailscale serve status --json > backups/serve-pre-4.0.0.json
pg_dump -Fc -d llmchat -f backups/llmchat-pre-4.0.0-$(date +%Y%m%d%H%M).dump
```

## 2. Create the user and directories **(sudo: 건영)**
```sh
sudo dscl . -create /Groups/_evegw
sudo dscl . -create /Groups/_evegw PrimaryGroupID 451
sudo dscl . -create /Groups/_evegw RealName "Eve gateway"
sudo dscl . -create /Users/_evegw
sudo dscl . -create /Users/_evegw UniqueID 451
sudo dscl . -create /Users/_evegw PrimaryGroupID 451
sudo dscl . -create /Users/_evegw UserShell /usr/bin/false
sudo dscl . -create /Users/_evegw NFSHomeDirectory /var/empty
sudo dscl . -create /Users/_evegw RealName "Eve gateway"
sudo dscl . -create /Users/_evegw IsHidden 1
sudo dscl . -create /Users/_evegw Password '*'

sudo install -d -o _evegw -g _evegw -m 0755 /opt/eve-gw /opt/eve-gw/bin /opt/eve-gw/web /opt/eve-gw/log
sudo install -d -o _evegw -g _evegw -m 0700 /opt/eve-gw/etc /opt/eve-gw/run
```

## 3. Install binary, config and secrets **(sudo: 건영)**
```sh
cd ~/llm-serving
sudo install -o _evegw -g _evegw -m 0755 bin/gateway-4.0.0 /opt/eve-gw/bin/gateway
sudo rsync -a --chown=_evegw:_evegw web/ /opt/eve-gw/web/
sudo install -o _evegw -g _evegw -m 0600 .api_key /opt/eve-gw/etc/api_key
sudo install -o _evegw -g _evegw -m 0600 config.yaml /opt/eve-gw/etc/config.yaml
sudo -e /opt/eve-gw/etc/config.yaml
```
In that editor:
- `log_file: /opt/eve-gw/log/gateway.log`
- `static_dir: /opt/eve-gw/web`
- `database.url:` paste the current `GW_DATABASE_URL` value from the old plist. Copy it in the editor; don't echo it.
- `unix_socket: /opt/eve-gw/run/gw.sock`
- If a `tools_killswitch_file` is used, move it under `/opt/eve-gw/etc/` (0600). The kill switch requires the file to be owned by the gateway uid.

## 4. LaunchDaemon **(sudo: 건영)**
Write `/tmp/com.llmserving.gateway.plist` *(no sudo)*. It has the same non-secret env as the 3.1.0 LaunchAgent, minus `GW_DATABASE_URL`:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.llmserving.gateway</string>
  <key>UserName</key><string>_evegw</string>
  <key>GroupName</key><string>_evegw</string>
  <key>ProgramArguments</key><array>
    <string>/opt/eve-gw/bin/gateway</string>
    <string>-config</string><string>/opt/eve-gw/etc/config.yaml</string>
    <string>-key-file</string><string>/opt/eve-gw/etc/api_key</string>
    <string>-host</string><string>127.0.0.1</string><string>-port</string><string>8000</string>
  </array>
  <key>EnvironmentVariables</key><dict>
    <key>GW_ENV</key><string>prod</string>
    <key>GW_ALLOWED_ORIGINS</key><string>https://&lt;TS_HOST&gt;</string>
    <key>GW_ALLOWED_USERS</key><string>(same as old plist)</string>
    <key>GW_DB_AUTO_MIGRATE</key><string>false</string>
    <key>GW_PUSH_ENABLED</key><string>false</string>
    <key>GW_WEB_ENABLED</key><string>(same as old plist)</string>
    <key>GW_SEARXNG_URL</key><string>(same as old plist)</string>
    <key>GW_UNIX_SOCKET</key><string>/opt/eve-gw/run/gw.sock</string>
  </dict>
  <key>WorkingDirectory</key><string>/opt/eve-gw</string>
  <key>StandardOutPath</key><string>/opt/eve-gw/log/gateway.launchd.log</string>
  <key>StandardErrorPath</key><string>/opt/eve-gw/log/gateway.launchd.log</string>
  <key>RunAtLoad</key><true/><key>KeepAlive</key><true/><key>ThrottleInterval</key><integer>15</integer>
</dict></plist>
```
Switch over. Downtime runs from bootout to serve switch, about 1 minute:
```sh
launchctl bootout gui/$(id -u)/com.llmserving.gateway                         # (no sudo) stop the 3.1.0 agent
mv ~/Library/LaunchAgents/com.llmserving.gateway.plist ~/llm-serving/backups/  # (no sudo) so it won't load at login
sudo install -o root -g wheel -m 0644 /tmp/com.llmserving.gateway.plist /Library/LaunchDaemons/com.llmserving.gateway.plist
sudo plutil -lint /Library/LaunchDaemons/com.llmserving.gateway.plist
sudo launchctl bootstrap system /Library/LaunchDaemons/com.llmserving.gateway.plist
```
Verify:
```sh
curl -s 127.0.0.1:8000/health                 # (no sudo) "version":"4.0.0"
sudo ls -l /opt/eve-gw/run                    # srw-rw----  _evegw _evegw  gw.sock
ps -axo user,pid,comm | grep '/opt/eve-gw/bin/gateway'   # user _evegw
tail -3 /opt/eve-gw/log/gateway.log           # gateway_start ... "unix_socket":true
```
If startup fails with `refusing to start: unix socket dir ... mode`, fix it with `sudo chmod 0700 /opt/eve-gw/run` and `sudo chown _evegw:_evegw /opt/eve-gw/run`.

## 5. Point `tailscale serve` at the socket *(no sudo: Tailscale CLI as the operator user)*
```sh
tailscale serve --https=443 off
tailscale serve --bg --https=443 unix:/opt/eve-gw/run/gw.sock
tailscale serve status        # https://<TS_HOST> (tailnet only) |-- / proxy unix:/opt/eve-gw/run/gw.sock
tailscale funnel status       # must show no funnel
```
Smoke test:
- From the iPhone or a tailnet browser, open `https://<TS_HOST>/ui`. It should log in as the allowlisted user, send a chat and save it.
- On the Mac, this must return **401**:
  ```sh
  curl -s -o /dev/null -w '%{http_code}\n' -H 'Tailscale-User-Login: <allowlisted login>' 127.0.0.1:8000/whoami
  ```
- With the API key on TCP, `/whoami` must report `"user":"api-key"`.

### Optional pf rule **(sudo: 건영)**
This is defense in depth. Only `_evegw` and 건영 may open TCP connections to 127.0.0.1:8000.
- macOS pf `user` matching applies to sockets owned by local processes.
- Test it first with `sudo pfctl -vnf`.
- macOS updates can reset `/etc/pf.conf`; re-check after updates.
```sh
printf 'pass  out quick on lo0 proto tcp from any to 127.0.0.1 port 8000 user { _evegw, <ME> }\nblock return out quick on lo0 proto tcp from any to 127.0.0.1 port 8000\n' | sudo tee /etc/pf.anchors/eve-gw
sudo cp -p /etc/pf.conf /etc/pf.conf.pre-eve
echo 'anchor "eve-gw"
load anchor "eve-gw" from "/etc/pf.anchors/eve-gw"' | sudo tee -a /etc/pf.conf
sudo pfctl -vnf /etc/pf.conf && sudo pfctl -f /etc/pf.conf && sudo pfctl -E
```
Remove it with `sudo cp -p /etc/pf.conf.pre-eve /etc/pf.conf && sudo pfctl -f /etc/pf.conf`.

## 6. Phase 2 (later): close TCP :8000 **(sudo: 건영)**
Do this when `grep '"auth_provider":"api-key"' /opt/eve-gw/log/gateway.log` has been empty for 7 days.
1. Add `<key>GW_TCP_DISABLED</key><string>true</string>` to the daemon plist.
2. Restart: `sudo launchctl bootout system/com.llmserving.gateway` then `sudo launchctl bootstrap system /Library/LaunchDaemons/com.llmserving.gateway.plist`.
3. Health checks then need `sudo curl --unix-socket /opt/eve-gw/run/gw.sock http://x/health`.

## 7. Future deploys
`/opt/eve-gw/bin/gateway` is owned by `_evegw`, so each deploy needs sudo:
```sh
sudo install -o _evegw -g _evegw -m 0755 bin/gateway-X /opt/eve-gw/bin/gateway
sudo launchctl kickstart -k system/com.llmserving.gateway
```

## 8. Rollback to 3.1.0 (about 2 minutes)
Restore the old setup in this order:
```sh
tailscale serve --https=443 off                                             # (no sudo)
sudo launchctl bootout system/com.llmserving.gateway
sudo mv /Library/LaunchDaemons/com.llmserving.gateway.plist /opt/eve-gw/etc/daemon.plist.disabled
cp -p ~/llm-serving/backups/com.llmserving.gateway.plist ~/Library/LaunchAgents/   # or the .pre-4.0.0 copy
cp -p ~/llm-serving/bin/gateway.v3.1.0.bak ~/llm-serving/bin/gateway
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.llmserving.gateway.plist
tailscale serve --bg --https=443 http://127.0.0.1:8000                      # (no sudo)
curl -s 127.0.0.1:8000/health                                               # "version":"3.1.0"
```
- No DB migration is involved, so the schema stays as it is.
- `_evegw` and `/opt/eve-gw` can stay. They are harmless while unused. To remove them: `sudo dscl . -delete /Users/_evegw`, `sudo dscl . -delete /Groups/_evegw` and `sudo rm -rf /opt/eve-gw`. That deletes files, so confirm first.
- Rolling back reopens the HIGH (loopback identity trust).

## Commands that need 건영's sudo
1. §2: all `dscl . -create ...` lines (user and group `_evegw`), and both `install -d` lines.
2. §3: `install` of the binary, api key and config, the `rsync --chown` of `web/`, and `sudo -e` of the config.
3. §4: `install` of the plist into `/Library/LaunchDaemons`, `plutil -lint`, `launchctl bootstrap system ...`, and the `ls`/`chmod`/`chown` checks and fixes on `/opt/eve-gw/run`.
4. §5 (optional pf): `tee /etc/pf.anchors/eve-gw`, the `cp`/`tee -a` of `/etc/pf.conf`, and `pfctl`.
5. §6 and §7: `launchctl bootout/bootstrap/kickstart system/...`, `install` of new binaries, and `curl --unix-socket` (the socket dir is 0700).
6. §8: `launchctl bootout system/...`, `mv` of the daemon plist, and optional removal of the user and directory.

Everything else needs no sudo: build, backups, the LaunchAgent bootout, `tailscale serve`/`funnel` and the curl checks on TCP.
