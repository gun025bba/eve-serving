## 1. Build exactly 98be55f *(no sudo)*
Replaces the "build from the PR head" block in §1. Stop if the SHA differs.
```sh
git fetch origin feat/unix-socket-identity && git worktree add ~/eve-4.0.0 98be55f1c13ffe1ae85e242be5f1f8d3d4c833b9
test "$(cd ~/eve-4.0.0 && git rev-parse HEAD)" = 98be55f1c13ffe1ae85e242be5f1f8d3d4c833b9 || { echo "SHA mismatch, stop"; exit 1; }
# 98be55f carries no v4.0.0 tag, so `git describe` would yield 3.1.1-N-g98be55f. The Makefile sets
# `VERSION ?=`, so a command-line VERSION overrides it; pass it explicitly. BIN is absolute.
(cd ~/eve-4.0.0 && make build VERSION=4.0.0 BIN="$HOME/llm-serving/bin/gateway-4.0.0")
"$HOME/llm-serving/bin/gateway-4.0.0" -version | grep -qx '4.0.0' || { echo "version is not 4.0.0, stop"; exit 1; }
```

## 4. No DB migration in this cutover
4.0.0 is built from the security-approved `98be55f` (untagged; the `v4.0.0` tag is added after a
successful deploy per the release rules) and is **not** rebased onto main. Its migrations are
`00001`–`00006` only (check: `git ls-tree --name-only 98be55f internal/store/postgres/migrations/`), so the
highest goose version it knows is **6**, which equals prod `llmchat` today. Nothing is migrated; `GW_DB_AUTO_MIGRATE=false` stays.
Check before cutover: `psql -d llmchat -Atc 'select max(version_id) from goose_db_version'` → `6`.
Rollback to v3.1.1 needs no DB step either.

## 6. Auth env guard before bootstrap (4.0.x with #58)
From the 4.0.x build that includes #58, `tailscale-identity` with an empty allowlist is a startup error
and launchd would crash-loop the gateway. Before every `launchctl bootstrap` / `kickstart -k` of
`system/com.llmserving.gateway`, run the guard; it prints no login values and exits non-zero to stop:
```sh
bash -euo pipefail <<'SH'
sudo deploy/check-auth-env.sh /Library/LaunchDaemons/com.llmserving.gateway.plist /opt/eve-gw/etc/config.yaml
SH
```
It passes only if the plist `GW_ALLOWED_USERS` (or config `allowed_users`) has a non-blank login, or
`GW_AUTH_PROVIDERS` (or config `auth.providers`) excludes `tailscale-identity` (e.g. `api-key`). On
failure, fix the plist/config and re-run; do not bootstrap. (4.0.0 at 98be55f predates #58, so this
check is a safe no-op there but must pass from 4.0.x on.)
