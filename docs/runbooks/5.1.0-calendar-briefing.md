# 5.1.0 — 캘린더 연동·아침 브리핑 (M1): switches, defaults, enabling

Everything in this feature is **off by default**. Merging or installing it changes nothing a user can see
until the owner turns a switch on, and turning the write switch on is an **external sync** (see below).

## The five gateway keys

| Key | Default | What it does | Needs |
|---|---|---|---|
| `GW_PIM_ENABLED` | `false` | Server switch for the read tools (`calendar_list_events`, `reminders_list`). Invalid value = start fails. | `GW_PIM_SOCKET_PATH` (absolute) and `GW_PIM_OWNER_USER_ID` (> 0) or the gateway refuses to start |
| `GW_PIM_SOCKET_PATH` | empty | The eve-pim helper's unix socket (absolute path). | helper running as the owner, socket dir 0750 group `_evepim` |
| `GW_PIM_OWNER_USER_ID` | `0` | The one `users.id` whose Calendar/Reminders the tools may read. | integer > 0 |
| `GW_BRIEFING_ENABLED` | `false` | Server switch for the morning briefing preview (`POST /v1/briefing/preview`). No scheduler in 5.1.0. Invalid value = start fails. | owner opt-in per user (`PATCH /v1/settings`) |
| **`GW_PIM_WRITES_ENABLED`** | `false` | Lets the owner's model **propose** `calendar_add_event`, `reminders_add`, `reminders_complete`. Proposals are only confirmation cards. Ignored unless `GW_PIM_ENABLED=true`. | helper started with `--writes-enabled` (second, independent switch) |

None of these can be set through `/v1/settings` or `/admin/config`; they are environment (or `pim:` / `briefing:` config) only.
`install-calendar-adapter.sh` writes `GW_PIM_ENABLED=false`, `GW_PIM_WRITES_ENABLED=false` and `GW_BRIEFING_ENABLED=false` if they are absent and never sets anything to `true`.

## Writes are an external sync — owner approval required

An event created by `calendar_add_event` (and a reminder created or completed) is written to the Mac's
Calendar/Reminders, which sync to the linked accounts (iCloud, Exchange, Google). Turning on **both**
`GW_PIM_WRITES_ENABLED=true` **and** the helper's `--writes-enabled` therefore needs the owner's explicit approval.
Neither flag is set by any install or deploy script.

What the owner sees before anything is written:
- The model only creates a card. Nothing is written until the owner approves it in a browser session
  (`interactive` scope; an API key gets 403).
- `calendar_add_event` **requires `calendar_id`** (taken from a `calendar_list_events` result, a writable calendar).
  The card always shows that calendar's name next to the exact title, time, place and notes. There is no
  "default calendar" path, so the target of the sync is never implicit (review finding L-1).
- Approve re-validates the card, re-checks the flags and that the calendar is still writable, writes the audit row
  (hash only) and makes exactly one helper call. An unknown outcome is not retried (no idempotency key in EventKit).

## Data left behind, and its cleanup

- Event/reminder text of a card lives in `pending_actions.payload` and `payload_view` while the card is open.
  A job in the gateway (every 6 h, also at start) blanks both to `{}` for finished pim write cards
  (approved, rejected, voided, expired) 24 h after they ended. `payload_hash` and the status stay. It runs even
  when pim is switched off, so cards from an earlier period are still cleaned up.
- Logs and audit rows carry only the method, a count, an error code and the payload hash — never event content.

## Limits worth knowing

- Titles shown to the model or put in the briefing are cut to 200 characters (`…`).
- Text fields refuse control characters, zero-width/format characters and U+2028/U+2029 (gateway and helper use the same rule).
- The helper answers one request per connection and gives up on a request that has not fully arrived 3 seconds after it connected.

## Turning things on (owner only), in this order, one at a time

1. Reads: set `GW_PIM_SOCKET_PATH`, `GW_PIM_OWNER_USER_ID`, then `GW_PIM_ENABLED=true`; approve the Calendar/Reminders (TCC) prompts once. Check with a chat question about today's events.
2. Briefing: `GW_BRIEFING_ENABLED=true`, then the owner's own opt-in in settings. Preview only.
3. Writes (needs separate explicit approval, see above): `GW_PIM_WRITES_ENABLED=true` and the helper LaunchAgent with `--writes-enabled`.

Undo is the same keys back to `false` (and, for the helper, removing `--writes-enabled`); no data migration is involved.
