# Wiring the #58 auth guard into the #23 (4.0.x) daemon runbook

Not applied to #23 (feat/unix-socket-identity, 98be55f) on purpose: 4.0.0 ships from that exact SHA.
This must be done on the 4.0.x branch **before #58 merges into anything that is deployed as the
daemon**, otherwise an empty allowlist crash-loops `system/com.llmserving.gateway`.

Guard call (prints names/counts only, exit 1 = stop):
`sudo deploy/check-auth-env.sh <new-binary> /Library/LaunchDaemons/com.llmserving.gateway.plist /opt/eve-gw/etc/config.yaml || exit 1`

Line numbers are as of 98be55f.

| File | Line | Insert the guard |
|---|---|---|
| `docs/runbooks/4.0.0-unix-socket.md` §4 | 170 | before `sudo launchctl bootstrap system /Library/LaunchDaemons/com.llmserving.gateway.plist` (after `sudo plutil -lint` on 169); binary `/opt/eve-gw/bin/gateway` installed in §3 line 87 |
| `docs/runbooks/4.0.0-unix-socket.md` §6 step 2 | 244 | before the `bootstrap` in the restart step |
| `docs/runbooks/4.0.0-unix-socket.md` §7 | 250–257 | before line 250 `sudo install ... bin/gateway-X`, using `bin/gateway-X` (check the new binary before it replaces the old one) |
| `docs/runbooks/4.0.0-unix-socket.md` §9 | 283, 288 | before each `kickstart -k` (config/key rotation) |
| `docs/runbooks/4.0.0-commands-for-geonyoung.md` | rows 6, 9, 13 | add the guard command to the sudo command list next to `bootstrap` / `kickstart -k` |

Notes for the #23 change:
- §4 generates the plist with an env allowlist that has `GW_ALLOWED_USERS` but not `GW_AUTH_PROVIDERS`.
  Guidance for API key only is `auth.providers: [api-key]` in `/opt/eve-gw/etc/config.yaml`.
- The 98be55f binary has no `-check-auth-config` flag; the guard needs a build that includes #58.
