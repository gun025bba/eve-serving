# Music.app 실측 프로브 — 실행·검증 절차 (이슈 #82)

> **보안 리뷰 완료 후 실행.** 스크립트는 읽기 전용이다. 설계: `docs/architecture/apple-music-playlist.md`.

## 1. 읽기 전용 프로브 (스크립트가 하는 일)
```
bash scripts/poc/music-probe.sh
```
- 건영의 macOS 로그인 세션 터미널에서 실행한다(헬퍼와 같은 GUI 세션 조건). 네트워크는 쓰지 않는다.
- Music.app이 꺼져 있으면 Apple Events 때문에 앱이 실행된다(재생은 하지 않음). TCC 자동화 팝업이 뜨면 **건영이 직접** 허용한다.
- stdout JSON에는 통계·소요 시간만 나온다(곡 제목·아티스트·앨범·경로 없음). 플레이리스트 이름은 기본 제외이며 `MUSIC_PROBE_NAMES=1`을 건영이 직접 줄 때만 포함된다.
- 측정 항목: 라이브러리 트랙 수, 전체 트랙 메타 일괄 읽기 시간(`bulk_read.fetch_only_ms`와 속성별 `per_property.*.ms`), 플레이리스트 목록(스마트 여부·트랙 수), played count / played date / skipped count / date added / rating 균등 간격 샘플 5개, macOS·Music 버전, TCC 상태(`granted`/`denied`/`timeout`/`error`)와 `first_call_ms`.
- 종료 코드: 0 = 권한 통과, 2 = 권한 거부·시간 초과·macOS 아님, 3 = 읽기 전용 자체 점검 실패.
- 결과 JSON을 이슈 #82 코멘트나 `docs/architecture/music-poc.md`에 붙일 때는 건영이 내용을 보고 올린다(개인 데이터 없음 확인).

## 2. 쓰기 검증(duplicate / delete) — 스크립트는 하지 않는다. 수동 절차만
**`delete` 검증은 버려도 되는 라이브러리에서만** 한다(보안 리뷰 High-2: `delete`가 참조 해석에 따라 라이브러리 항목까지 지울 수 있음). 이 PoC가 끝나 '플레이리스트 항목만 지워짐'이 확인되기 전에는 `playlist_remove`를 구현하지 않는다. 건영이 직접 참관하며, 스크립트로 자동화하지 않는다.

**0. 버리는 라이브러리 준비** (건영 직접, 실제 라이브러리는 건드리지 않는다)
- 별도 macOS 사용자 계정 또는 Music 앱의 임시 새 라이브러리(앱 실행 시 Option 키로 라이브러리 선택 — 가능 여부는 PoC에서 확인)를 쓴다. 실제 보관함은 미리 백업한다. **iCloud 음악 보관함 동기화를 끄는 것은 필수**다: 임시 라이브러리·계정에서 동기화를 끄고(설정 > 일반 > 'Sync Library' 해제), 꺼졌는지 확인한 뒤에만 아래 1단계를 시작한다. 끌 수 없거나 꺼졌는지 확인할 수 없으면 PoC를 중단한다(`delete`가 iCloud로 전파되어 실제 보관함에 영향을 줄 수 있음).
- 임시 라이브러리에 시험용 곡 몇 개(로컬 파일이면 충분)를 넣는다.

**1. 빈 테스트 플레이리스트에서 단계별로**
1. 임시 라이브러리에 새 플레이리스트 `eve-poc-test`(이름은 임의)를 만들고 **비어 있는지 확인**한다.
2. 시험용 곡 1개를 건영이 고른다(곡 이름은 보고서에 적지 않는다).
3. 스크립트 에디터에서 `duplicate`로 `eve-poc-test`에 넣는다. 확인: 성공 여부, 에러 코드, 플레이리스트 곡 수 변화.
4. **스냅샷 먼저**: 지우기 전에 플레이리스트의 (플레이리스트 id, track id, 위치) 목록을 기록한다(설계 §7.1-4와 같은 형식).
5. 같은 곡을 **해당 플레이리스트의 요소로서** `delete`한다. 확인: **라이브러리에 곡이 남아 있는지**(핵심), 파일이 남아 있는지, 플레이리스트 곡 수 감소. 같은 곡이 플레이리스트에 중복일 때의 동작도 확인한다.
6. 스마트 플레이리스트·폴더에서 같은 동작이 거부되는지는 **건영이 만든 시험용 항목**으로만 확인한다. Library 플레이리스트에는 `delete`를 보내지 않는다.
7. 동기화는 꺼 둔 상태이므로 iCloud 전파 시간은 이 PoC에서 측정하지 않는다(동기화가 꺼진 채로 끝났는지 마지막에 다시 확인한다). iCloud 전파 확인은 별도 승인 후 `playlist_add`로만 한다.
8. 끝나면 `eve-poc-test`와 임시 라이브러리·계정은 건영이 직접 지운다.
9. 결과는 성공/실패와 에러 코드만 기록한다(곡·플레이리스트 이름 제외).
